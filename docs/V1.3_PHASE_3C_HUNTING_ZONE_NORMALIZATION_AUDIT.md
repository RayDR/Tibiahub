## 3. Root cause of 973 legacy-only zones

All 974 `HuntZone` domain rows originated from the legacy Creature-location bridge, not from a Hunting Zone provider import. During the 2026-08-03 Creature batch, `_ensure_hunt_zone` converted every distinct free-text value in `Creature.locations` into a domain `HuntZone`, then `SpawnLocation` linked Creatures to it. This path bypassed Knowledge documents, entity normalization, provider mappings, and identity review.

An old 2026-08-12 TibiaMaps sync subsequently stamped 973 rows with `source_provider=tibiamaps`, global map bounds/centroid, and a global floor image. That was enrichment/overwriting, not their origin, and did not provide per-zone marker identity. Current code had already deprecated that unsafe geometry path. Iksupan alone was later normalized from a real TibiaWiki Hunting Zone detail document.

Cause quantification:

| Cause | Zones |
|---|---:|
| `LEGACY_IMPORT_BYPASSES_KNOWLEDGE` | 973 |
| Real HuntZone normalizer run with provider document | 1 |
| `MISSING_EXTERNAL_ID` on legacy rows | 973 |
| Missing HuntZone raw document/mapping on legacy rows | 973 |
| Exact existing HuntZone identity available for safe recovery | 0 |
| Ambiguous exact HuntZone identities in development data | 0 |
| Normalizer lacks HuntZone support | 0 |
| Mapping write failure demonstrated | 0 |

Creating 973 entities from these rows would canonize free text and category/prose values as real zones. Phase 3C therefore fixes the ingestion boundary and normalizes the relationship evidence without fabricating identities.

## 5. Canonicalization algorithm

Hunting Zone entity creation remains restricted to genuine Hunting Zone provider catalog/detail documents. The repaired HuntZone normalizer:

1. reuses an existing canonical provider mapping;
2. resolves a stable provider/external identity;
3. reuses one unique, same-entity-type exact canonical name or verified alias;
4. fails safely on multiple exact candidates;
5. otherwise creates an entity only because the input is a canonical HuntZone provider document, never because another entity referenced text.

Creature location evidence is normalized separately to `Creature --appears_in--> HuntingZone`. A preloaded, same-type HuntZone exact index resolves a unique target, records multiple candidates as ambiguous, or records no candidate as unresolved. It never creates the target entity.

## 6. Identity resolution precedence

The effective precedence is provider mapping → stable exact provider identity → unique normalized exact canonical name → unique verified exact alias → ambiguous/unresolved. Matching uses the existing casing/spacing normalization contract. Cross-entity-type, substring, Levenshtein, fuzzy, and LLM fallbacks do not exist in this path.

## 7. Provider mapping behavior

The sole canonical zone retains TibiaWiki mapping `101544`. Provider mappings are written through the Knowledge mapping contract, inside collision-safe transactional handling. Replay reuses the existing mapping. A mapping already owned by another entity fails rather than being reassigned. Display names are not manufactured into external IDs. TibiaMaps markers remain marker evidence, not HuntZone provider mappings.

## 8. Alias behavior

Only explicit provider alternative names/page titles and existing verified aliases participate. Canonical casing/spacing normalization makes replay idempotent. Alias collision is a warning/conflict and never an arbitrary resolution. No token fragments, stripped suffixes, generated variants, or fuzzy aliases were added. Iksupan's canonical name alias remains the only stored HuntZone alias in this dataset.

## 9. Creature normalization behavior

The normal production Creature normalizer now translates each supplied `locations` value to an exact Knowledge relationship. It records source scope `hunt_zone_locations`, source provider, raw document, job/run, confidence, target name, candidate IDs, state, and reason. Existing current relationships are reconciled; missing prior evidence is retired by the normal Knowledge graph contract. The direct legacy Creature sync now preserves all location strings, continues to link already-existing legacy bridge rows, and creates a new `HuntZone` bridge only when exactly one existing canonical HuntZone identity can be resolved. It no longer converts arbitrary text into zones.

Resolution produced 11 exact relationships to Iksupan and 4,759 unresolved references. Six opposite-direction Iksupan `has_creature` relationships already existed; projection merges those duplicates with `appears_in` and legacy Spawn evidence.

## 10. Quest normalization behavior

Only the one canonical Iksupan HuntZone document contains zone-level Quest evidence. Its source contract marks the Quest as required access, yielding one resolved `requires_hunt_quest` relationship. No current zone source evidence justifies `unlocks_access` or generic `related` creation. Generic/public Quest display data remains display evidence and is not silently promoted to access semantics. Unresolved access remains explicitly unresolved in the projection.

## 11. Location normalization behavior

The pipeline keeps city, region prose, canonical Location identity, and geometry separate. Iksupan's structured city target `Port Hope` is retained as one unresolved `located_at` reference because no exact canonical Location entity exists; its region prose remains prose. The 973 legacy strings do not provide structured Location targets. No prose, category page, direction, or city co-location was converted into a Location entity or geometry.

## 12. TibiaMaps marker behavior

Only canonicalized zones were considered. Iksupan has no exact marker/provider/verified-alias candidate, so it remains `knowledge_only`; no coordinate or bounds were created. Across all legacy names, an audit found 100 unique exact marker names, 25 ambiguous exact marker names, and 849 with no exact marker, but those legacy names are not canonical zone identities and therefore were not linked. Exact same text is insufficient when the marker is already typed as another entity—for example, the exact `Goshnar's Cruelty` marker resolves to a Creature, not a Hunting Zone. Tests prove exact same-type marker association and rejection of a near-name/fuzzy association.

## 14. EXP/profit findings

Coverage remains zero. The one real HuntZone provider document contains qualitative labels/ratings such as “Good,” not reliable numeric hourly EXP/profit with unit and context. The adapter is not dropping a reliable numeric source value. Unknown remains unknown.

## 15. Level/vocation findings

Iksupan supplies minimum level 150 and a provider vocation recommendation matrix. The other 973 rows' zero/false domain defaults have no provider provenance and continue to project as unknown. No level was inferred from Creatures and no vocation was inferred from difficulty.

## 16. Ambiguity behavior

Ambiguity is a first-class Knowledge relationship state with candidate IDs and `MULTIPLE_CANDIDATES`. Entity normalization raises a typed conflict when multiple same-type exact candidates exist. Provider and alias collisions fail safely. Development data currently has zero ambiguous HuntZone identities and zero ambiguous Creature-to-zone relationships; test fixtures cover both cases. Marker ambiguity is tracked independently and is never automatically selected.

## 17. Unresolved behavior

The 973 legacy rows remain honestly legacy/unresolved identities. Of 4,770 current Creature location references, 4,759 are current unresolved Knowledge relationships with `NO_CANDIDATE`; they are not duplicated on replay. Source prose and category strings remain source text. Existing graph/review contracts are reused instead of adding a Phase-specific unresolved enum.

## 18. Provenance behavior

## 29. Performance observations

The repair preloads the small HuntZone exact index and processes Creature documents in bounded batches, avoiding query-per-relationship target lookup and avoiding loading the entire Knowledge graph into Python. With batch size 250: dry-run took 31.56 seconds and about 107.7 MB maximum RSS; first apply took 28.52 seconds and about 107.9 MB; replay took 21.86 seconds and about 108.0 MB. Nine batches processed 2,202 Creatures and 4,770 references. This scale does not justify distributed processing.

## 39. NPC-related findings for Phase 3F

No trustworthy HuntingZone↔NPC relationship vocabulary or source coverage was found in this dataset. Location/city co-occurrence must not be used to infer an NPC association.
