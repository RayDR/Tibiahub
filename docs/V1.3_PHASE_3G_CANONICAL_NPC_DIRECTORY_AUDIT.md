# TibiaHub V1.3 Phase 3G — Canonical NPC Directory Audit

Date: 2026-09-03. Scope: Phase 3G only. The figures below are read-only measurements of the development PostgreSQL database. No row was manually rewritten, staged, or committed.

## Architecture and identity

The normal production path is `TibiaWiki NPCs category -> npc_catalog jobs -> npc_detail job -> immutable KnowledgeDocument -> TibiaWikiNpcAdapter -> KnowledgeNormalizationService -> KnowledgeEntity/provider mapping/alias -> TibiaWikiNpc bridge`. All 46 current bridge rows came from the `tibiawiki` provider, have a canonical Knowledge UUID, a `tibiawiki` external mapping, an alias, an immutable detail document, and a traceable `npc_detail` job. Documents use `mediawiki-v1`, English source content, and were retrieved between 2026-07-26 and 2026-08-14.

`KnowledgeEntity.uuid` is canonical identity. `TibiaWikiNpc.id`, slug, and provider external ID remain compatibility bridges. New directory, detail, SEO, and map navigation prefer the UUID. Existing numeric/slug/provider paths remain accepted. No entity, alias, relationship, or coordinate is created by the public projection.

## API and discovery contract

`GET /api/v1/npcs/directory` is the new bounded list projection. It returns `items`, authoritative `total`, `skip`, and `limit`; defaults to 24 and caps at 100. Ordering is `(normalized_name, bridge_id)`. Search covers normalized canonical names, safe exact-normalized aliases, occupation, and documented location. The optional location filter is backed only by `location_name`. Search does not use fuzzy, substring-identity, LLM, or provider calls. The old `GET /api/v1/npcs/` list remains compatible.

Cards contain canonical UUID, name, title/occupation when present, documented location text, independently known/empty/unknown buy/sell/Quest/destination counts, safe-media state, and exact spatial state. The richer detail adds aliases, provenance, location graph facts, trade, generic Quest references, incoming canonical Quest relationships, destinations, and the shared Phase 3D spatial projection.

The directory is linked from the Cyclopedia menu and has a responsive 1/2/3/4-column layout. Search and location state are URL-addressable, debounced, abort stale requests, reset pagination when changed, and use server-side pagination. Cards and detail links use canonical NPC UUIDs.

## Semantics and relationships

- `buys` is labelled “NPC buys” and explicitly means items the player sells to the NPC.
- `sells` is labelled “NPC sells” and explicitly means items the player buys from the NPC.
- Prices are displayed only when supplied. The current adapter/source rows contain no reliable prices or currency facts; none are invented. `gp` is only appended to a supplied price under the current TibiaWiki trade contract.
- Item, Quest, and destination names resolve at read time only through an exact indexed canonical name or verified alias. One candidate links to the existing route; zero stays unresolved; multiple stay ambiguous. The original provider name remains visible.
- No new graph vocabulary was created for trade or travel. Current relationship vocabulary already represents Quest-to-NPC (`starts_at_npc`, `references_npc`, `mission_references_npc`) and NPC-to-place (`located_at`). Incoming Quest relationships are projected in the NPC perspective using their registered inverses.
- Location prose remains source text. It does not create a Location, marker, city-centre fallback, or shared-city relationship.
- Multiple exact graph locations are preserved as multiple locations. Because the provider model has no movement schedule/current-position field, the UI explicitly avoids claiming which is current.

The source currently has no canonical trade reference, Quest reference, or destination reference to link. The only apparent buy/sell value was the provider placeholder `--` on `A Skull`; this is now rejected by both adapter and projection as missing evidence. A normal provider replay removes it durably. No one-off database repair was run.

## Spatial and media behavior

The NPC projector reuses the Phase 3D exact spatial traversal. Trusted direct points/regions/links and explicitly resolved TibiaMaps markers are accepted; exact canonical `located_at` relationships may carry trusted location evidence. Name similarity never places an NPC. One NPC (`A Swan`) currently reaches a trusted point through its exact `located_at -> Edron` relation. Forty-two have unresolved location relationships and three are knowledge-only.

Map search now returns `/npcs/{canonical_uuid}` and no longer exposes the provider image URL. NPC-to-map links use the UUID-based Phase 3D query. Forty-six provider image references exist, but there is no NPC local-media cache/serving contract, so all are `reference_only`; safe media coverage is zero and semantic placeholders are used.

## Reciprocal and cross-domain findings

The Item model still has legacy `buy_from`/`sell_to` JSON, but the NPC source has no usable canonical trade evidence, and there is no canonical trade relationship vocabulary. Adding reciprocal Item-to-NPC links now would fabricate or duplicate interpretation, so Phase 3G does not do it. The next data phase should first ingest structured item/provider identities and price/currency semantics, then add one provenance-aware vocabulary contract if justified.

Quest detail already projects canonical Quest-to-NPC graph relationships and links resolved NPCs. Phase 3G adds the reciprocal NPC perspective without new storage. Current development data has zero such relationships. Hunting Zones and the Hunt Planner have no trustworthy direct NPC relationship in current vocabulary/data; shared Location is not treated as a relationship. A later planner enhancement should consume NPC services only after authoritative Zone/Quest/NPC links exist.

NPC category/role is limited to provider title and occupation. These are displayed as source facts, not converted into an inferred taxonomy. Imported Tibia names, descriptions, roles, and locations remain untranslated; only interface labels have English/Spanish translations.

## Performance and correction workflow

A representative production page of 24 out of 46 NPCs performed 15 bounded SQL statements in 651.7 ms including first connection/setup. Statement count is independent of relationship cardinality and there is no query per card or reference. Detail performs bounded batched canonical/alias queries per non-empty reference kind. The catalog never loads the full Knowledge graph into Python.

Existing unresolved/ambiguous graph locations and Quest relations remain visible in Admin Knowledge Review; no NPC-specific review system was added. Raw trade/destination names are deliberately not inserted into unsupported graph vocabulary. Provider replay is the durable correction mechanism for the parser placeholder fix.

## Missing data and recommended next phase

Primary gaps are upstream/ingestion coverage, not UI: only 46 NPCs, 44 location texts but 42 unresolved location targets, one trusted spatial result, no usable trade/Quest/destination data, no prices/currency, and no locally cached media. The recommended next V1.3 phase is a bounded **NPC provider coverage and relationship normalization** phase: expand/replay the catalog, parse structured trade prices and external item identities, normalize exact Quest/destination evidence through existing Knowledge Review, and add a compliant local NPC media pipeline. It should precede any Hunt Planner NPC-service suggestions.
